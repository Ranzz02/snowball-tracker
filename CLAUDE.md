# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Snowball Tracker: an Electron desktop app for tracking an Escape from Tarkov "snowball" achievement run. One friend is the hunter, the others are helpers who are paid in roubles for boss kills, PMC kills and similar, and docked for deaths and team kills. The app keeps a ledger of what each helper has earned, been paid and is still owed. React 19 + TypeScript 6 + Zustand 5 + Tailwind 4 in the renderer, built with Vite 8 via `vite-plugin-electron`, on Electron 45. (README.md is the unmodified Vite template and has no project-specific information.)

## Commands

The package manager is Yarn 4, pinned through the `packageManager` field in `package.json` and run through corepack. Don't use npm, because it would create a `package-lock.json`.

- `yarn install`: installs dependencies. `.yarnrc.yml` sets `nodeLinker: node-modules` because electron-builder needs a real `node_modules` folder and doesn't support Plug'n'Play.
- `yarn dev`: starts Vite and launches Electron with HMR. `vite-plugin-electron` also builds `electron/main.ts` and `electron/preload.ts` into `dist-electron/`.
- `yarn build`: `tsc && vite build && electron-builder`. Installers go to `release/<version>/` (NSIS on Windows, DMG on Mac, AppImage on Linux; config is in `electron-builder.json5`). `yarn electron-builder --dir` writes an unpacked build to `release/<version>/win-unpacked/` without creating an installer.
- `yarn tsc --noEmit`: typecheck only.
- `yarn test`: Vitest, unit tests for `src/lib/` (`yarn vitest run src/lib/payouts.test.ts` for one file, `-t "name"` for one test).
- `yarn lint`: ESLint 10 using the flat config in `eslint.config.js`, with `--max-warnings 0`, so any warning fails it.
- `yarn format` / `yarn format:check`: Prettier, configured in `.prettierrc`. Code uses tabs (width 4), single quotes, semicolons, trailing commas and a print width of 100. YAML, Markdown and `package.json` use 2 spaces. `eslint-config-prettier` turns off ESLint rules that would conflict with Prettier.

The tests cover only the pure logic in `src/lib/`. There are no component or end-to-end tests.

Yarn refuses package versions published less than a day ago (`npmMinimalAgeGate`, 1440 minutes by default). If an install fails with "All versions satisfying ... are quarantined", lower the version range to an older release. Don't disable the gate.

TypeScript stays on `~6.0`, because `typescript-eslint` doesn't support TypeScript 7 yet.

Build output (`dist/`, `dist-electron/`, `release/`) is git-ignored and regenerated by `yarn dev` / `yarn build`.

## Architecture

**Process split.** The renderer never touches the filesystem. `electron/preload.ts` exposes a small typed `window.api` (`loadData`, `saveData`, `exportData`, `importData`, `openDataFolder`; types in `electron/electron-env.d.ts`) through `contextBridge`. `electron/main.ts` implements the matching `ipcMain.handle` calls. All app data is one JSON file, `app-data.json`, in `app.getPath("userData")/data/`. It is written to a temp file and renamed, so a crash cannot leave it half-written. The dev app and the installed app use the same folder (`%APPDATA%\snowball-tracker`).

**Data model** (`src/models.ts`, `AppData`, `schemaVersion: 2`): `Run` has `raids: Raid[]`. A `Raid` has `bosses: {bossId, killed}[]` and `helpers: Record<friendId, RaidHelper>`. A `RaidHelper` records `pmcKills`, `teamKills`, `died`, `extracted` and `adjustments` (signed one-off bonuses and penalties). Helpers are stored once per raid, not once per boss. Each raid also holds `rates`, a snapshot of the global `Rates` taken when the raid was created, so changing Settings never rewrites old raids (Settings has an "Apply to open run" button for when you do want that). Penalty rates are stored as positive numbers and subtracted by the payout engine. The hunter (`run.hunterId`) is a friend but is never a helper in that run.

**Payouts are never stored, always computed** (`src/lib/payouts.ts`, pure functions): `raidLines` produces labelled `{category, label, amount}` lines per helper, `runBreakdown` adds up the raids and the completion bonus, `ledger` totals earned, paid (from `payments`) and owed per friend, and `bossProgress` reports required bosses killed or remaining. Every screen gets its numbers from these functions. Do not duplicate payout math in components. Rules worth knowing:

- Base pay is per boss killed, per helper.
- A hunter death ends the run: `setHunterDied(true)` sets the run to `abandoned`, and clearing the last death reopens it. Kills from a `hunterDied` raid don't count toward `bossProgress` or completion, but helpers still get base pay for them, minus the hunter-death penalty.
- The completion bonus is paid only when the run status is `completed` and every required boss is dead.
- `requiredBossIds` empty means all bosses count.

**State.** One Zustand store with the immer middleware, `src/store.ts` (`useGameStore`). Actions mutate drafts, using `withRaid(runId, raidId, fn)` for raid edits. `initializeStore()` (once, guarded against StrictMode double-run) loads through `window.api`, runs `migrate()` and subscribes. Changes are saved after a 300 ms debounce, and again on `beforeunload`. The saved shape is `toAppData(state)`. Components pick fields with selectors. Bosses and maps come from `src/data/bosses.json` and `src/data/maps.json` (boss `group: "goons"` groups the three Goons in the UI).

**Migration** (`src/lib/migrate.ts`): `migrate(raw, bosses)` accepts v1 data or v2 and returns v2. v1 was four separate files (`runs.json`, `friends.json`, `reward-config.json`, `active-run-id.json`) in two raid shapes (one boss on the raid itself, or `bosses[].rewards`). On first launch with no `app-data.json`, main merges the four files, copies them to `backup-v1-<timestamp>/`, and the renderer migrates them. Hand-edited base pay in old data is preserved as an adjustment so totals do not change. `pickRates` drops rate keys that no longer exist, such as the removed streak rates. Imported backups also go through `migrate()`.

**UI.** `App.tsx` is a sidebar (Run, Ledger, Friends, Settings) plus a top bar showing the open run's hunter, boss progress and payout. Run screens live in `src/components/runs/`: `RunsTab` shows either `RunList` or, when `activeRunId` is set, `RunDashboard` (boss checklist, squad, map picker, raid list). `raids/RaidEditor.tsx` is a drawer for editing one raid. `components/ledger/LedgerTab.tsx` handles settle-up and payment history. Text summaries for Discord are built in `src/lib/summary.ts`. Shared primitives are in `src/components/ui/`: `ui.tsx` (Button, Panel, Stepper, Toggle, NumberInput and so on), `Overlays.tsx` (Modal, Drawer, and the `FeedbackHost` that must be mounted once), and `feedback.ts` (the `toast()` and promise-based `confirmAction()` helpers, used instead of `window.confirm`).

**Styling.** Dark-only Tarkov-style theme. Tailwind 4 is set up through the `@tailwindcss/vite` plugin, with design tokens in the `@theme` block of `src/index.css` (`bg-surface`, `bg-panel`, `text-ink`, `text-mute`, `text-accent`, `text-ok`, `text-danger` and so on). There is no `tailwind.config` or PostCSS config. Fonts (Rajdhani for headings, Inter for body) are bundled with `@fontsource` because the app runs offline. The `label-caps` utility gives the uppercase heading look. A small `@layer base` block restores two Tailwind 3 defaults: the default border color and `cursor: pointer` on buttons.

**Packaging.** `electron-builder.json5` sets `"publish": null`. Without it `electron-builder` crashes after building the installer, because there is no publish target or repository.
